# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

React + Tailwind CSS (SPEC.md에서 사용자가 지정). 빌드 도구는 위임받아 Vite를 골랐다. 이미지 처리는 브라우저의 Canvas API로 한다. 서버가 없다.

## Users

전문 지식이 없는 일반인. 사진 용량 제한이 있는 곳(원서 접수, 게시판, 메신저 등)에 사진을 올려야 하는데 파일이 너무 클 때, 휴대폰이나 PC에서 잠깐 들러 한 장을 줄이고 나간다.

## Product Purpose

사진 한 장을 사용자가 적은 목표 용량 이하로 줄여 준다. 원하면 확장자도 바꾼다. 성공은 사용자가 사진을 올리고, 숫자를 적고, 버튼을 한 번 눌러 목표 용량 이하의 파일을 받는 것이다.

## Positioning

로그인이 없고, 사진이 기기 밖으로 나가지 않는다(모든 처리가 브라우저 안에서 일어난다). 꼭 필요한 기능 외에는 아무것도 없다.

## Operating Context

- 흐름: 사진 올리기 → 기존 용량·해상도·확장자 확인 → 목표 용량 입력 → (선택) 확장자 고르기 → 줄이기 → 자동 저장 → 전후 비교 확인
- 데스크톱과 모바일 브라우저 모두에서 쓴다. 끌어다 놓기를 지원한다.

## Capabilities and Constraints

- 사진은 한 번에 한 장만 다룬다.
- 목표 용량은 숫자를 직접 입력하고 단위(KB/MB)를 고른다. 프리셋 버튼은 없다.
- 확장자는 드롭박스로 고른다: JPG, WebP, PNG. 처음 값은 원래 확장자.
- 압축은 화질 손상을 최소화한다. 1단계로 품질을 낮추고, 그래도 목표에 못 미치면 2단계로 가로세로 비율을 유지하며 해상도를 단계적으로 줄인다.
- 변환이 끝나면 저장 버튼 없이 즉시 저장한다. 파일 이름은 `원본이름_compressed.확장자`. 브라우저가 자동 저장을 막았을 때를 위한 "다시 저장" 버튼이 있다.
- 변환 뒤에는 전후 용량, 줄어든 비율, 전후 사진, (바뀌었다면) 전후 해상도를 보여준다.
- 올린 사진의 파일 이름은 표시하지 않는다. "다른 사진 줄이기" 버튼은 없다("다른 사진 고르기"는 있다).
- 로그인, 계정, 서버 업로드, 기록 보관 기능은 없다.

## Evidence on Hand

요구사항 문서 `SPEC.md`, 사용자와 확정한 화면 구조 `.agents/screendoro-draft.md`. 후기, 사용자 수, 수치 같은 근거는 없으므로 지어내지 않는다.

## Product Principles

1. 꼭 필요한 것만 둔다. 새 요소는 "이걸 빼면 사용자가 정보나 기능을 잃는가"로 판단한다.
2. 사용자가 정한 숫자를 지킨다. 목표 용량을 못 맞추면 숨기지 않고 알린다.
3. 화질을 먼저 지킨다. 해상도 축소는 품질 조절로 안 될 때만 한다.
4. 사진은 기기를 떠나지 않는다.

## Accessibility & Inclusion

전문 용어 없이 쉬운 한국어를 쓴다. 키보드만으로 모든 동작을 할 수 있어야 하고, 모바일에서 한 손으로 쓸 수 있어야 한다.
